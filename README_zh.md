# PC-98 游戏厅（原型）

[English](README.md) | **简体中文**

基于 **Godot 4.7.2-stable** 的 PC-98 模拟器前端，内核为 **NP2kai**（Neko Project II kai，libretro 版，IA32 CPU）。
界面风格参考 Steam / Epic 游戏库，首次启动默认英文（English），可切换为简体中文 / 繁體中文 / 日本語，选择后会记住（见第 7 节）。

> 本程序**不附带**任何 BIOS、字体 ROM 或游戏镜像，请使用您自己合法拥有的文件。
> **BIOS 是可选的**：不放入真机 BIOS 也能直接开始游戏（与 NP2 相同，使用内置兼容 BIOS + 系统字体生成的字库），见第 3 节。

---

## 1. 下载文件（三个版本 + 工程）

| 文件 | 内容 | 用法 |
|---|---|---|
| `PC98_Godot_Project.zip` | 完整 Godot 4.7 工程（已包含编译好的 GDExtension：Windows `.dll` 与 Linux `.so`） | 用 Godot 4.7.2 打开 `project.godot`，按 **F5** 运行，无需编译任何代码 |
| `PC98_Windows.zip` | 已导出的 Windows 版本 | 解压后双击 `PC98GameHall.exe` |
| `PC98_Linux.tar.gz` | 已导出的 Linux 版本（x86_64，X11） | 解压后运行 `./PC98GameHall.x86_64`（见第 13 节） |
| `PC98_Android.apk` | 安卓版（arm64-v8a，适用于几乎所有 2017 年以后的安卓手机 / 平板） | 拷到手机上点击安装（见第 12 节） |
| `PC98_Android_x86_64.apk` | 安卓版（x86_64，用于安卓模拟器 / 部分 Chromebook） | 同上，普通手机请用上一个 |

Windows 导出版目录（三个文件必须放在同一文件夹；界面与脚本已嵌入 exe，没有单独的 .pck）：

```
PC98GameHall.exe                                 程序（Godot 4.7.2 精简版运行时 + 已嵌入的界面与脚本）
libpc98.windows.template_release.x86_64.dll      GDExtension（PC98Emulator 节点）
np2kai_libretro.dll                              NP2kai 模拟器内核
data\                                            首次运行后自动生成：全部设置与数据（便携模式，见第 8 节）
```

系统要求：Windows 10/11 64 位，显卡支持 OpenGL 3.3（使用 Godot 的“兼容”渲染器）。

## 2. 用 Godot 编辑器打开工程

1. 下载 Godot **4.7.2-stable**（标准版，非 .NET 版）。
2. 在项目管理器中“导入”，选择解压后的 `project.godot`。
3. 首次打开会自动导入资源，然后按 **F5** 运行。
4. **自己导出**（不需要任何自定义模板）：
   1. 编辑器菜单 **编辑器 → 管理导出模板…**，点 **下载并安装**，装好 **4.7.2.stable 官方导出模板**（只需装一次）。
   2. **项目 → 导出…**，选择 **Windows Desktop**（或 Linux / Android），点 **导出项目**，
      选好输出文件夹后保存即可。“导出为调试”可以勾也可以不勾：不勾 = 正式版（推荐），勾上 = 调试版（标题带 (DEBUG)，略慢）。
   3. 工程里的导出预设已经清空了自定义模板路径，会自动使用官方模板，不会再出现
      “自定义导出模板可执行文件架构不匹配：发现了 invalid”的错误。
   - 官方模板导出的程序比我提供的安装包大一些（官方 exe 约 104–109 MB、Linux 程序约 70 MB，
     我提供的包使用的是去掉不用模块的精简模板，exe 约 37 MB），功能完全相同。
   - 导出后的文件夹里应有 `PC98GameHall.exe`、`libpc98.windows.template_release.x86_64.dll`、
     `np2kai_libretro.dll` 三个文件（预设已开启“嵌入 PCK”，界面与脚本在 exe 里面，所以没有 .pck），请整个文件夹一起复制。
     若只有 .dll 而没有 .exe，说明导出失败了，请看导出窗口里的红色错误。
   - 运行导出的程序后，设置和数据会保存在 exe 旁边的 `data` 文件夹（便携模式，见第 8 节）；
     在编辑器里按 F5 运行时仍使用系统的用户数据目录，两者互不影响。

GDExtension 位于 `addons/pc98/`，`pc98.gdextension` 会在导出时自动把 `np2kai_libretro.dll` 复制到 exe 旁边。

## 3. BIOS（可选）

和 NP2 一样，**不放 BIOS 也能运行**：

| | 内置兼容 BIOS（不放 BIOS 时） | 真机 BIOS（放入 `bios.rom` 等时） |
|---|---|---|
| 需要的文件 | 无 | 您自己机器上导出的 `bios.rom`（及 `itf.rom`、`sound.rom` 等） |
| 来源 | NP2kai 内核自带的兼容 BIOS（模拟 BIOS 调用 + 内置 ITF） | 真实 PC-98 的 ROM |
| 汉字 / 假名字库 | 用系统字体自动生成（见第 4 节） | 有 `FONT.ROM` / `font.bmp` 时使用字体 ROM，否则同样用系统字体生成 |
| 兼容性 | 大多数从软盘 / 硬盘启动的游戏可以运行 | 最好；直接调用 ROM 内部例程、依赖 N88-BASIC(86) ROM 或声卡 BIOS 的少数软件需要真机 BIOS |
| 界面提示 | 左下角显示黄色「● 内置 BIOS」，开始游戏时提示「未放入真机 BIOS，正在使用内置兼容 BIOS，放入真机 BIOS 兼容性更好」 | 左下角显示绿色「● BIOS 已就绪」 |

实测（本仓库的测试 HDI 游戏）：BIOS 文件夹为空或未设置时，内置 BIOS 自检 → MS-DOS 6.20 启动 → 游戏标题画面，与真机 BIOS 时得到的标题画面逐像素相同。
没有 `sound.rom` 时 FM 音源仍可正常发声（游戏一般直接操作音源芯片）；没有 `2608_*.wav` 时 YM2608 节奏音源没有声音。

如果您有真机 BIOS，想获得更好的兼容性：

1. 把您自己的 PC-98 BIOS 文件放进一个文件夹，例如 `D:\PC98\BIOS`：

   | 文件 | 说明 |
   |---|---|
   | `bios.rom` | 主 BIOS（没有时使用内置兼容 BIOS） |
   | `itf.rom` | ITF ROM（推荐） |
   | `sound.rom` | 声卡 BIOS（推荐） |
   | `font.bmp` 或 `FONT.ROM` | 汉字字体 ROM（可选，见下文“字体”） |
   | `2608_bd.wav` `2608_sd.wav` `2608_top.wav` `2608_hh.wav` `2608_tom.wav` `2608_rim.wav` | YM2608 节奏音源采样（可选） |
   | `bios9821.rom` | PC-9821 BIOS（可选，没有也能正常运行） |

   文件名大小写均可（`BIOS.ROM`、`FONT.ROM` 等大写文件名会自动复制为小写）。
   没有 `font.bmp` 时自动使用 `FONT.ROM`；两者都没有时用系统字体生成字库（见下文）。

2. 打开程序 → 左侧 **设置** → **BIOS 文件夹**，选择该文件夹，下方会显示检测结果。
3. 每次开始游戏时，这些文件会自动复制到模拟器系统目录 `<数据目录>/system/np2kai/`（数据目录见第 8 节）；
   BIOS 文件夹里已删除的文件，其旧副本也会同时删除。所以清空或取消 BIOS 文件夹后，会马上改用内置兼容 BIOS。

## 4. 字体（与 NP2 相同的三种方式）

在 **设置 → 字体 → 字体来源** 中选择：

1. **自动**：使用 BIOS 文件夹中的 `font.bmp` / `FONT.ROM`。
2. **指定字体文件**：手动选择任意位置的 `FONT.ROM` 或 `font.bmp`。
3. **系统字体生成**：没有字体 ROM 时，用 TrueType 字体生成汉字字库（`font.tmp`）。
   选择“自动”但 BIOS 文件夹里没有字体 ROM（包括完全不放 BIOS）时，也会自动改用这种方式。
   默认是 `C:/Windows/Fonts/msgothic.ttc`（MS Gothic），也可以选择其它日文字体（`.ttf / .ttc / .otf`）。
   如果设置中的字体文件在这台电脑上不存在，程序会按顺序自动寻找：
   MS Gothic → 游ゴシック → Meiryo → MS Mincho → Noto Sans CJK → 微软雅黑 → 宋体 → 黑体 …
   （中文版 Windows 未安装“日语补充字体”时会使用微软雅黑 / 宋体，假名可以显示，但字形不如日文字体地道）。
   - Linux：自动寻找 Noto Sans CJK、IPA ゴシック、VL Gothic、Takao、文泉驿等，都找不到时用 `fc-list :lang=ja` 查找任意日文字体。
   - 安卓：使用系统自带的 `/system/fonts/NotoSansCJK-Regular.ttc`（或 Droid Sans Fallback）。
   - 完全找不到日文 / 中文字体时**不会崩溃**：英文和数字照常显示（NP2 内置半角字形），假名和汉字显示为 `?` 或空白。

游戏运行中也可以通过菜单 **字体** 切换，切换后立即重新加载字库，不需要重启。

## 5. 添加游戏

**设置 → 添加游戏**：

- **FDD1 / FDD2 软盘**：`FDI`（推荐），也支持 `D88 / 88D / D98 / HDM / XDF / DUP / 2HD / TFD / NFD` 等。
- **HDD 硬盘**：`HDI`，也支持 `NHD / THD / VHD / SLH`。
- 两张软盘的游戏可以同时选择 FDD1 与 FDD2；硬盘游戏选择 HDI。
- **封面**：可选 png / jpg；不选则自动生成渐变封面。也可以在游戏详情页点击“更换封面…”。

添加后在 **游戏库** 中点击游戏 → **开始游戏**。玩过的游戏会出现在 **最近游玩**，并记录游玩时间。

### 5.1 游戏库文件夹（自动递归扫描）

游戏很多时，不必一个个添加：**设置 → 游戏库文件夹** 选择存放游戏的总文件夹，程序会递归扫描所有子文件夹，自动加入游戏库。
游戏库页右上角的 **⟳ 扫描游戏库** 按钮（或设置中的 **⟳ 扫描 / 刷新游戏库**）可随时重新扫描；勾选 **启动时自动扫描游戏库文件夹**（默认开启）后，每次启动都会在后台刷新一次。

**扫描规则**（示例：`D:/PC98/Games`）：

```
D:/PC98/Games/
├─ 天神乱魔.hdi                 → 1 款游戏「天神乱魔」（未分类）
├─ あ/                          → 分类「あ」
│  ├─ あすか120%.hdi            → 1 款游戏
│  ├─ アークス.fdi              → 1 款游戏
│  └─ ア・ラ・モード/           → 1 款多碟游戏「ア・ラ・モード」
│     ├─ Disk1.fdi                 FDD1 = Disk1，FDD2 = Disk2
│     ├─ Disk2.fdi                 换盘列表：Disk1、Disk2、Disk10（自然排序）
│     └─ Disk10.fdi
├─ R/                           → 分类「R」
│  ├─ Rusty.hdi                 → 1 款游戏
│  └─ RPG/                      → 既有镜像又有子文件夹：
│     ├─ Bonus.fdi                 Bonus.fdi 单独算 1 款游戏
│     └─ Lodoss/                   子文件夹继续递归 → 多碟游戏「Lodoss」
│        ├─ Disk A.fdi
│        └─ Disk B.fdi
└─ OS/                          → 分类「OS」
   └─ MS-DOS 6.2/               → 多碟游戏（3 张）
```

| 情况 | 结果 |
|---|---|
| 单独的镜像文件 | 1 款游戏，游戏名 = 文件名（不含扩展名） |
| **第一层文件夹**（如 `あ`、`R`、`OS`） | **分类**，显示在卡片上，可用游戏库左上角的分类下拉框筛选；分类文件夹本身不会被当成游戏 |
| 第二层及更深、**只包含镜像**（没有子文件夹）的文件夹 | **1 款多碟游戏**，游戏名 = 文件夹名；软盘按文件名自然排序（Disk1、Disk2 … Disk10）组成换盘列表 |
| 同时包含镜像和子文件夹的文件夹 | 其中每个镜像各算 1 款游戏，子文件夹继续递归 |
| 只包含子文件夹的文件夹 | 继续向下递归 |
| 只包含 2 个以上硬盘镜像、没有软盘的文件夹 | 每个硬盘镜像各算 1 款游戏 |
| 多碟游戏里既有硬盘镜像又有软盘 | 从硬盘启动，软盘放在换盘菜单里 |

- **支持的扩展名**（不区分大小写）：
  - 硬盘：`hdi nhd thd vhd slh`，以及 `hdd hdn hds`（这三种在 NP2kai 中只用于 SCSI，挂到 HDD1 可能无法启动）
  - 软盘：`fdi d88 88d d98 98d hdm xdf dup 2hd tfd nfd fdd hd4 hd5 hd9 h01 hdb ddb dd6 dcp dcu fim`
  - `img ima flp dsk` 这类通用扩展名只在文件 ≤ 2 MB（软盘大小）时才当作软盘，避免把其它大文件误认为游戏
  - `fdx` 不被 NP2kai 支持，因此不扫描
- **会跳过**：小于 512 字节的文件、无法读取的文件、以 `.` 开头的隐藏文件夹、`__MACOSX`、`$RECYCLE.BIN`、`System Volume Information`、`BIOS` 文件夹；最多递归 12 层。文件名 / 文件夹名可以包含日文、中文和空格。
- **原位置使用，不复制**：镜像不会被复制到程序中；游戏库里记录的是相对于游戏库文件夹的路径，所以整个游戏文件夹换盘符 / 换位置后，只要在设置里重新选择文件夹即可。软盘的写回（存档）直接保存在原镜像中。
- **多碟换盘**：游戏中按 `Esc` / `F12` 打开菜单 → 「FDD1」或「FDD2」，下方「本游戏的软盘（共 N 张）」列出这个游戏的所有软盘，点击即可换盘（● 表示当前插入的盘）。
- **去重**：按文件路径去重，重复扫描不会出现重复的游戏；已经手动添加过的同一个镜像也不会再加入一次。游玩记录、改过的名称和封面在重新扫描后保留。
- **移除 / 隐藏**：在详情页点击「从游戏库移除」，扫描到的游戏会被**隐藏**（不删除镜像，重新扫描也不会再出现）；设置里的「恢复已隐藏的游戏」可以全部恢复。
- **文件缺失**：镜像被删除、移动或移动硬盘没有插上时，游戏不会被删除，而是在卡片上显示「⚠ 文件缺失」，启动时给出提示，不会闪退。文件恢复后重新扫描即可。
- 如果把一个多碟游戏文件夹里又加了子文件夹，按规则它会被拆成多个游戏，原条目的游玩记录不会保留。
- **数量很多时**：扫描在后台线程进行，界面上显示进度；卡片分批显示（每次 240 张，底部「显示更多」），几千款游戏也不会卡顿。可以用搜索框和分类筛选快速查找。
- 手动添加（设置 → 添加游戏）的游戏和扫描到的游戏可以同时存在。
- **安卓版**：游戏库文件夹留空时，使用「导入」页中的导入文件夹 `Android/data/com.pc98.gamehall/files/PC98/`，可以在里面按分类建子文件夹，规则同上；也可以填写本应用有权限读取的其它文件夹路径。安卓系统的文件夹选择器返回的 `content://` 地址无法直接扫描。

## 6. 游戏中的操作

| 按键 | 功能 |
|---|---|
| **Esc** 或 **F12** | 打开 / 关闭游戏菜单（暂停） |
| **Alt + Enter** | 切换窗口 / 全屏（与 NP2 相同，游戏库界面中也可用） |
| **窗口最大化按钮 / 双击标题栏** | 进入全屏（与 Alt + Enter 相同） |
| **Esc**（游戏库界面） | 退出全屏 |

设置中勾选“**ESC 键发送给 PC-98**”后，Esc 会发送给游戏，菜单改用 F12 打开。

### 游戏内鼠标（PC-98 总线鼠标）

很多 PC-98 游戏（例如 亜紀子 等带箭头光标的 AVG）需要用鼠标点选。Windows / Linux 版可以把电脑鼠标直接当作 PC-98 的总线鼠标使用：

| 操作 | 功能 |
|---|---|
| 开始 / 继续游戏 | 鼠标自动**锁定**到游戏画面（系统光标隐藏），移动鼠标 = 移动游戏里的光标 |
| 鼠标左键 / 右键 | PC-98 鼠标左键 / 右键 |
| **鼠标中键** 或 **Ctrl + F10** | 释放鼠标（系统光标重新出现，可以移到窗口外）；再按一次重新锁定 |
| 鼠标已释放时，**左键点击游戏画面** | 重新锁定（这一下不会发送给游戏） |
| **Esc / F12** 打开菜单、切换到其他窗口 | 自动释放鼠标；点 **▶ 继续** 后重新锁定 |
| 游戏菜单中的 **鼠标：开 / 关** 按钮（在「画面」旁边） | 开 / 关游戏内鼠标；关闭后只用键盘，系统光标自由移动 |

- **设置 → 模拟器 → 启用游戏内鼠标（PC-98 总线鼠标）**：默认开启；与菜单中的「鼠标」按钮是同一个开关。
- **设置 → 模拟器 → 鼠标灵敏度**（0.25× – 4×，默认 1.00×）：1.00× 时游戏光标在屏幕上移动的距离与电脑鼠标相同（已按画面缩放 / 黑边换算）。
- 鼠标锁定时屏幕上方会提示「鼠标已锁定到游戏画面 · 中键或 Ctrl+F10 释放」；底部状态栏也显示这两个热键。
- Alt + Enter 全屏、Esc / F12 菜单在鼠标锁定时照常可用。
- 游戏要自己支持鼠标（游戏里有箭头光标）才会有反应；只支持键盘的游戏不受影响。
- 安卓版的“触控板”鼠标（在画面上滑动移动、点按 = 左键、双指点按 = 右键）也使用同一个总线鼠标；以前的版本没有打开内核的鼠标输入，所以触控板鼠标实际上不起作用，这个版本已修复。

### 游戏菜单（类似 NP2）

- **FDD1 / FDD2**：插入软盘… / 弹出 / 插入该游戏登记的软盘镜像
- **⇄ 交换软盘**：交换 FDD1 与 FDD2 中的软盘
- **HDD**：挂载 / 卸载 HDD1、HDD2（硬盘更换后需要 **重置** 才能生效）
- **字体**：切换字体来源
- **画面**：选择画面缩放方式（4:3 等比例 / 原始比例 / 整数倍放大），以及切换全屏
- **鼠标：开 / 关**：开 / 关游戏内鼠标（PC-98 总线鼠标，见上一节）
- **↺ 重置**：相当于按下 PC-98 的复位键（软盘保持插入）
- **⏻ 重新启动**：完全断电后重新启动模拟器
- **⛶ 全屏**、**▶ 继续**、**返回游戏库**

**换盘方法**（与 NP2 相同）：游戏要求换盘时，直接在菜单中插入下一张软盘即可；
需要从新软盘启动时，插入后再点 **↺ 重置**。

| F1 – F10 | f·1 – f·10（F12 保留给菜单；NP2kai 内核暂不支持 vf·1 – vf·5） |

设置中可选择键盘布局（美式 US 101 / 日式 JIS 106）与机型（PC-9801VX / VM / PC-286）。

### 全屏（Alt+Enter / 最大化按钮，等比例放大）

- 在游戏中或游戏库界面按 **Alt + Enter** 即可在窗口与全屏之间切换，与 NP2 的操作相同；
  也可以点击游戏菜单的 **⛶ 全屏** 按钮，或 **设置 → 显示 → 切换到全屏**。
- 点窗口右上角的 **最大化（□）按钮**（或双击标题栏）效果与 Alt + Enter **完全相同**：直接进入等比例黑边全屏，
  和 Alt + Enter 共用同一个全屏开关；之后按 **Alt + Enter** 会回到最大化之前的窗口位置和大小（普通窗口，不是最大化）。
  Windows 11 的贴靠布局（拖到左右半屏等）不会触发全屏。
- 全屏时画面会**按比例放大到最大**，左右（或上下）多余部分用黑边填充，**不会拉伸变形**；
  改变窗口大小时也会自动保持比例。
- Alt + Enter 不会发送给 PC-98（游戏不会收到 Enter），切换后会自动松开所有按键，避免按键卡住。
- 游戏中 **Esc** 仍然用于打开菜单（与 NP2 相同）；要退出全屏请再按一次 **Alt + Enter**。
- 是否全屏会被记住，下次启动时自动恢复。
- 窗口标题出现 **(DEBUG)** 说明是在 Godot 编辑器里直接运行的项目（编辑器运行较慢）；导出的 PC98GameHall.exe 标题没有 (DEBUG)。
- 全屏或大窗口下，游戏库 / 设置 / 详情等界面会**限制最大宽度并居中显示**（两侧留白），不会把文字和输入框拉满整个屏幕；窗口较小时则自动铺满。
- 画面缩放方式（**设置 → 显示 → 画面缩放**，或游戏菜单 **画面**）：

  | 方式 | 说明 |
  |---|---|
  | **4:3 等比例**（默认，推荐） | 按当年 CRT 显示器的 4:3 比例显示 640×400 画面，与真机观感一致 |
  | **原始比例** | 640×400（16:10）方形像素，不做纵向拉伸 |
  | **整数倍放大** | 2 倍、3 倍等整数倍放大，像素边缘清晰（周围黑边会更多） |

## 7. 多语言切换

- 支持 **English**（首次启动默认）、**简体中文**、**繁體中文**、**日本語**。
- 切换方法：左侧栏底部的 🌐 语言下拉框，或 **设置 → 界面语言 → 语言**。切换后立即生效，

  “项目设置 → 本地化”，并在 `scripts/i18n.gd` 的 `LOCALES` / `LANG_NAMES` 中添加即可。

## 8. 数据保存位置（便携模式）

**Windows / Linux 导出版是“便携版”**：所有设置和数据都保存在程序旁边的 `data` 文件夹里（首次运行时自动创建），
不写注册表，也不往 `%APPDATA%` / `~/.local/share` 里存数据。

```
PC98GameHall\
├─ PC98GameHall.exe（Linux：PC98GameHall.x86_64）   ← 界面与脚本已嵌入，没有单独的 .pck
├─ libpc98.….dll / .so、np2kai_libretro.dll / .so   ← 必须和程序放在一起，不能删除或移走
└─ data\
   ├─ settings.json        设置
   ├─ library.json         游戏库
   ├─ system\np2kai\       模拟器系统目录（BIOS 副本、np2kai.cfg、字库）
   ├─ bios\、games\        用“导入”功能复制进来的 BIOS / 游戏镜像（如有）
   └─ PC98\                “导入文件夹”（如有）
```

- **搬家 / 换电脑 / 放进 U 盘：把整个文件夹复制过去即可**，设置、游戏库、导入的 BIOS 和游戏都会一起带走。
- 建议把 BIOS 文件夹和游戏镜像也放在程序文件夹里面（例如 `PC98GameHall\BIOS\`、`PC98GameHall\游戏\`）：
  程序文件夹内的路径会以**相对路径**保存，换了盘符或目录也能找到；放在程序文件夹外面的文件按原来的绝对路径记录，
  复制到别的电脑后需要在那里重新选择。
- 游戏镜像不会被自动复制，库中只记录路径；对软盘的写入会直接写回原镜像文件，请自行备份。
- 想恢复初始状态：退出程序后删除 `data` 文件夹。
- **第一次以便携模式运行时**，如果系统用户目录里有旧版本保存的设置 / 游戏库，会自动复制一份到 `data`（只复制一次，旧文件保留不动）。
- **程序文件夹不可写时**（例如装在 `C:\Program Files` 下、只读的 U 盘），自动改用系统用户目录：
  - Windows：`%APPDATA%\PC98GameHall\`
  - Linux：`~/.local/share/PC98GameHall/`（若设置了 `$XDG_DATA_HOME`，则为 `$XDG_DATA_HOME/PC98GameHall/`）
  想要便携，请把程序放在普通文件夹（如 `D:\Games\PC98GameHall\`、桌面、文档）。
  启动参数 `-- --no-portable` 也可以强制使用系统用户目录。
- **在 Godot 编辑器里运行（F5）时**始终使用上面的系统用户目录，不会在工程文件夹里生成 `data`。
- 当前使用的位置显示在 **设置 → 关于** 中（便携模式时会注明）。
- 说明：Godot 引擎启动时总会在系统用户目录建立一个空的 `PC98GameHall` 文件夹（引擎本身的行为，里面不保存任何东西；
  引擎日志和着色器缓存已关闭）。启动游戏时模拟器内核会临时复制一份到系统临时目录（`%TEMP%` / `/tmp`）再加载，退出后删除，这不是用户数据。
- 安卓：不变，使用应用私有目录（`user://`），导入的 BIOS 在 `bios/`，镜像在 `games/`。

## 9. 出错时的行为（防崩溃保护）

模拟器内核的每一次调用（载入、首帧初始化、运行、换盘、重置、切换字体等）都被异常保护包裹：
如果内核因为损坏的 BIOS / 镜像等原因发生内存访问违例等致命错误，程序**不会闪退**，
而是停止模拟、返回游戏库并弹出“**模拟器核心错误**”对话框，显示出错阶段与错误代码。
之后可以检查 BIOS 文件夹 / 镜像，再次点击“开始游戏”（每次开始游戏都会重新载入一个全新的内核副本）。

### 修复记录：HDI 游戏点击“开始游戏”后立即闪退（Windows）

原因是内核 Windows 版构建脚本中的一处错误补丁：`dosio.c` 的文件打开函数返回了 C 运行库的 `FILE*`，
而读取 / 定位 / 关闭函数却把它当作 libretro 的 `RFILE*` 使用，导致首帧初始化读取 `np2kai.cfg` 时
读到错误长度并发生缓冲区溢出（只在 Windows 版出现，且没有任何输出）。已修正并重新编译
`np2kai_libretro.dll` 与 `.so`，并用真实 BIOS + HDI 游戏验证可以启动到游戏标题画面。

## 11. 原型的限制

- Windows 版在 Wine 环境下用真实 BIOS 与 HDI 游戏测试过（可启动到 MS-DOS 与游戏标题画面）；尚未在真实 Windows 电脑上测试。
- 内置兼容 BIOS 在 Linux 版和 Wine 下的 Windows 版用一款 HDI 游戏测试过（可启动到标题画面）；安卓版没有在真机上测试内置 BIOS。少数软件（N88-BASIC、直接调用 ROM 例程或声卡 BIOS 的程序）需要真机 BIOS。
- 防崩溃保护在 Wine 下验证有效，真实 Windows 上未验证；内核内部线程中的崩溃无法拦截。
- FDI 软盘游戏尚未用真实游戏测试。
- 声音输出尚未在真实声卡上验证。
- 没有存档状态（即时存档）与手柄映射。
- 游戏内鼠标用自制的 PC-98 鼠标测试程序（Linux 版与 Wine 下的 Windows 版，模拟鼠标事件）验证过移动、左右键、释放 / 锁定；尚未在真实 Windows 电脑、真实鼠标和安卓真机上测试，也未用具体的鼠标游戏逐一测试。
- 硬盘镜像更换后需要重置才生效。
- 全屏 / 等比例缩放与多语言切换在 Linux 下测试过，尚未在真实 Windows 电脑上测试全屏。
- 安卓版：在 x86_64 安卓模拟器（软件渲染）上验证了界面、导入、游戏库与触屏按键；模拟器里速度太慢，未能看到游戏画面。用 `adb push` 推送的文件夹应用可能无权读取，请用 USB 文件传输（MTP）或应用内的「导入」页；应用首次启动时会自动创建 `Android/data/com.pc98.gamehall/files/PC98/BIOS` 文件夹。
- Linux 版只在 Debian 13（X11 / Xvfb，软件 OpenGL）下测试过，尚未在 Wayland 桌面和真实显卡上测试；没有 ARM64 Linux 版本。

### 安装

1. 把 `PC98_Android.apk` 拷到手机上，用文件管理器点击安装（需要在系统设置中允许“安装未知来源应用”）。

### 导入 BIOS 与游戏（底部「导入」页）

安卓应用不能随意读取手机里的文件，所以要先把 BIOS 和镜像**导入**到应用中：

| 按钮 | 作用 |

| **导入 BIOS 文件夹…** | 打开系统文件选择器，选中存放 `bios.rom`、`itf.rom`、`sound.rom`、`font.bmp` / `FONT.ROM`、`2608_*.wav` 的文件夹，全部复制到应用中 |

| **导入游戏镜像…** | 选择一个 `.hdi` 硬盘镜像，或 1–2 张 `.fdi` 软盘镜像（按文件名顺序作为 FDD1 / FDD2），复制到应用中并加入游戏库 |
| **扫描导入文件夹** | 不想复制大文件时：用 USB 线或文件管理器把文件拷到 `Android/data/com.pc98.gamehall/files/PC98/`（BIOS 放在其中的 `BIOS` 子文件夹，游戏镜像放在 `PC98` 文件夹或按分类建的子文件夹中，规则见第 5.1 节），然后点这个按钮，镜像在原位置使用 |

本程序不附带任何 BIOS、字体 ROM 或游戏镜像。**BIOS 可以不导入**：没有 BIOS 时自动使用内置兼容 BIOS 和系统字体（见第 3 节），只需导入游戏镜像就能开始游戏。

### 手机界面

| 操作 | 说明 |
|---|---|
| 在画面上滑动 | 移动 PC-98 鼠标（触控板方式） |
| 单指点按 / 双指点按 | 鼠标左键 / 右键 |
